SaltyKeys.js is designed to be lightweight and performant with minimal impact on your application.

## Performance Overview

SaltyKeys.js has **negligible performance impact** in typical use cases:

| Operation | Time | Impact |
|-----------|------|--------|
| Library load | &lt;1ms | One-time |
| `getPenId()` (first call) | ~0.1ms | Cached after |
| `generateSaltedKey()` | ~0.2ms | Console only |
| `getApiKey()` (first call) | ~0.3ms | Per salted key |
| `getApiKey()` (cached) | ~0.05ms | Subsequent calls |

<Aside type="tip">
For reference, JavaScript execution of 1ms is typically imperceptible to users. SaltyKeys operations complete in microseconds.
</Aside>

## Library Size

**Unminified**: ~10KB
**Minified**: ~3KB
**Gzipped**: ~1.2KB

SaltyKeys.js is smaller than most analytics scripts and has zero dependencies.

## Built-In Optimizations

### 1. ID Caching

After the first call to `getPenId()`, the result is cached:

```js
// First call: parses URL with regex
const id1 = SaltyKeys.getPenId();  // ~0.1ms

// Subsequent calls: returns cached value
const id2 = SaltyKeys.getPenId();  // ~0.01ms
const id3 = SaltyKeys.getPenId();  // ~0.01ms
```

**Why it matters**: If you call `getApiKey()` multiple times, the ID extraction doesn't repeat.

**Control caching**:
```js
// Disable caching if the ID might change
SaltyKeys.configure({ cacheEnabled: false });
```

### 2. Lazy Execution

SaltyKeys operations only run when called:

```js
// Loading the library doesn't execute anything
<script src="SaltyKeys.js"></script>  // ~0ms impact

// Operations only happen when you call them
const key = SaltyKeys.getApiKey(salted);  // ~0.3ms
```

No background processes, no event listeners, no polling.

### 3. Efficient Encoding

Base64 encoding/decoding uses native browser APIs (`btoa`/`atob`) which are highly optimized:

```js
// Native implementation (fast)
const encoded = btoa(str);  // ~0.01ms for typical strings

// vs. a JavaScript polyfill (slower)
const encoded = manualBase64(str);  // ~1-5ms
```

## Performance Best Practices

### ✅ Do: Cache decoded keys

Don't decode the same key repeatedly:

**Bad** ❌
```js
function makeRequest() {
  // Decodes every time
  const key = SaltyKeys.getApiKey(SALTED_KEY);
  return fetch(`https://api.example.com?key=${key}`);
}

for (let i = 0; i < 100; i++) {
  makeRequest();  // 100 decode operations
}
```

**Good** ✅
```js
// Decode once
const API_KEY = SaltyKeys.getApiKey(SALTED_KEY);

function makeRequest() {
  return fetch(`https://api.example.com?key=${API_KEY}`);
}

for (let i = 0; i < 100; i++) {
  makeRequest();  // 1 decode operation
}
```

### ✅ Do: Initialize at startup

Decode keys during initialization, not in hot paths:

**Bad** ❌
```js
// Inside an animation frame
function animate() {
  const key = SaltyKeys.getApiKey(SALTED_KEY);  // Called 60x/sec
  drawFrame(key);
  requestAnimationFrame(animate);
}
```

**Good** ✅
```js
// Outside the loop
const API_KEY = SaltyKeys.getApiKey(SALTED_KEY);  // Once

function animate() {
  drawFrame(API_KEY);
  requestAnimationFrame(animate);
}
```

### ✅ Do: Use for appropriate workloads

SaltyKeys is designed for client-side API calls, not high-frequency operations:

**Appropriate** ✅
```js
// API calls: 1-10 per second
async function fetchData() {
  const key = SaltyKeys.getApiKey(SALTED_KEY);
  return fetch(`https://api.example.com?key=${key}`);
}
```

**Not appropriate** ❌
```js
// Gaming loop: 60+ per second
function gameLoop() {
  const key = SaltyKeys.getApiKey(SALTED_KEY);  // Unnecessary overhead
  updateGame(key);
}
```

### Memory Usage

SaltyKeys has minimal memory footprint:

- **Library code**: ~10KB in memory
- **Cached ID**: ~50 bytes
- **Per salted key**: ~200-500 bytes (the string itself)

For typical use (1-5 API keys), total memory impact is **&lt;15KB**.

## Comparison to Alternatives

| Approach | Performance | Security | Complexity |
|----------|------------|----------|------------|
| **Plain text keys** | Fastest | ❌ None | Simplest |
| **SaltyKeys obfuscation** | ~0.3ms overhead | ⚠️ Educational | Simple |
| **Server-side proxy** | +100-500ms (network) | ✅ Secure | Complex |

SaltyKeys provides a middle ground: minimal overhead with some protection.

## Optimization Patterns

### Pattern 1: Singleton Key Manager

```js
class ApiKeyManager {
  constructor() {
    // Decode once at initialization
    this.weatherKey = SaltyKeys.getApiKey(WEATHER_KEY_SALTED);
    this.mapsKey = SaltyKeys.getApiKey(MAPS_KEY_SALTED);
  }

  getWeatherKey() {
    return this.weatherKey;
  }

  getMapsKey() {
    return this.mapsKey;
  }
}

// Create once
const keys = new ApiKeyManager();

// Use many times (no decoding overhead)
const weather = await fetch(`api?key=${keys.getWeatherKey()}`);
const maps = await fetch(`api?key=${keys.getMapsKey()}`);
```

### Pattern 2: Lazy Initialization

```js
class ApiClient {
  constructor(saltedKey) {
    this._saltedKey = saltedKey;
    this._decodedKey = null;
  }

  get apiKey() {
    // Decode only when first accessed
    if (!this._decodedKey) {
      this._decodedKey = SaltyKeys.getApiKey(this._saltedKey);
    }
    return this._decodedKey;
  }
}
```

### Pattern 3: Module-Level Cache

```js
// api.js
let cachedApiKey = null;

export function getApiKey() {
  if (!cachedApiKey) {
    cachedApiKey = SaltyKeys.getApiKey(SALTED_KEY);
  }
  return cachedApiKey;
}

export async function fetchData(endpoint) {
  const key = getApiKey();  // Fast after first call
  return fetch(`${endpoint}?key=${key}`);
}
```

## When Performance Matters

### SaltyKeys is fast enough for:

✅ Typical API requests (1-10 per second)
✅ User-initiated actions (clicks, form submissions)
✅ Page initialization
✅ Periodic background tasks
✅ Educational demos and examples

### Consider alternatives for:

⚠️ High-frequency operations (>100/second)
⚠️ Real-time applications needing &lt;10ms latency
⚠️ Mobile devices with very limited CPU
⚠️ Battery-critical applications

<Aside type="note">
In practice, API rate limits (typically 1-100 requests/second) make SaltyKeys performance a non-issue. The network latency (50-500ms) dwarfs the ~0.3ms decoding time.
</Aside>
