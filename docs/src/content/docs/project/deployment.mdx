## When to Use SaltyKeys

### ✅ Appropriate Use Cases

- **CodePen demos** and tutorials
- **Educational content** and workshops
- **Documentation examples** with live code
- **Proof-of-concept** demonstrations
- **Public examples** where some protection is better than none

### ❌ Inappropriate Use Cases

- **Production web applications**
- **E-commerce sites**
- **Financial applications**
- **Healthcare applications**

- **Any application with sensitive data**

## Recommended Production Architecture

For real applications, use a **server-side API proxy** instead of client-side API keys.

### Architecture Diagram

```
┌─────────────────┐
│                 │
│  Client Browser │
│  (Your Web App) │
│                 │
└────────┬────────┘
         │
         │ 1. Request data
         │    (no API key)
         ↓
┌─────────────────┐
│                 │
│  Your API Proxy │
│  (Your Server)  │
│                 │
└────────┬────────┘
         │
         │ 2. Add API key
         │    (server-side)
         ↓
┌─────────────────┐
│                 │
│  External API   │
│  (3rd Party)    │
│                 │
└─────────────────┘
```

**Flow:**
1. Client makes request to YOUR server (no API key exposed)
2. Your server validates, rate-limits, and adds the API key
3. Your server proxies request to external API
4. Response flows back through your server
5. Client receives only the data it needs

## Server-Side Proxy Implementation

### Node.js + Express Example

```js
// server.js
const express = require('express');
const axios = require('axios');
require('dotenv').config();

const app = express();

// Middleware
app.use(express.json());

// Rate limiting
const rateLimit = require('express-rate-limit');
const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100 // limit each IP to 100 requests per windowMs
});
app.use('/api/', limiter);

// API proxy endpoint
app.get('/api/weather', async (req, res) => {
  try {
    // 1. Validate input
    const city = req.query.city;
    if (!city) {
      return res.status(400).json({
        error: 'City parameter required'
      });
    }

    // 2. Make request with server-side key
    const response = await axios.get(
      'https://api.weatherapi.com/v1/current.json',
      {
        params: {
          key: process.env.WEATHER_API_KEY, // Secure!
          q: city
        }
      }
    );

    // 3. Return only what the client needs
    res.json({
      temperature: response.data.current.temp_c,
      condition: response.data.current.condition.text,
      location: response.data.location.name
    });

  } catch (error) {
    console.error('API error:', error.message);
    res.status(500).json({
      error: 'Failed to fetch weather data'
    });
  }
});

app.listen(3000, () => {
  console.log('Proxy server running on port 3000');
});
```

```env
# .env (never commit this file!)
WEATHER_API_KEY=your-actual-api-key-here
```

```js
// client.js
async function getWeather(city) {
  // Call YOUR proxy, not the external API
  const response = await fetch(`/api/weather?city=${city}`);

  if (!response.ok) {
    throw new Error('Weather request failed');
  }

  return response.json();
}

// Usage
const weather = await getWeather('London');
console.log(weather);
// { temperature: 15, condition: 'Sunny', location: 'London' }
```

### Python + Flask Example

```python
# server.py
from flask import Flask, request, jsonify
import requests
import os
from dotenv import load_dotenv
from flask_limiter import Limiter
from flask_limiter.util import get_remote_address

load_dotenv()
app = Flask(__name__)

# Rate limiting
limiter = Limiter(
    app=app,
    key_func=get_remote_address,
    default_limits=["100 per hour"]
)

@app.route('/api/weather')
@limiter.limit("10 per minute")
def get_weather():
    # 1. Validate input
    city = request.args.get('city')
    if not city:
        return jsonify({'error': 'City parameter required'}), 400

    try:
        # 2. Make request with server-side key
        response = requests.get(
            'https://api.weatherapi.com/v1/current.json',
            params={
                'key': os.getenv('WEATHER_API_KEY'),  # Secure!
                'q': city
            }
        )
        response.raise_for_status()
        data = response.json()

        # 3. Return only what the client needs
        return jsonify({
            'temperature': data['current']['temp_c'],
            'condition': data['current']['condition']['text'],
            'location': data['location']['name']
        })

    except requests.RequestException as e:
        return jsonify({'error': 'Failed to fetch weather data'}), 500

if __name__ == '__main__':
    app.run(port=3000)
```

### Benefits of Server-Side Proxy

✅ **API keys never exposed** to client
✅ **Rate limiting** controlled by you
✅ **Request validation** before external API calls
✅ **Response filtering** — only send necessary data
✅ **Authentication** — verify user identity
✅ **Monitoring** — log and track usage
✅ **Cost control** — limit API usage
✅ **Error handling** — better error messages

## Security Best Practices

### 1. Environment Variables

**Never hardcode API keys:**

```js
// ❌ NEVER DO THIS
const API_KEY = 'sk-1234567890abcdef';

// ✅ DO THIS
const API_KEY = process.env.API_KEY;
```

Use `.env` files (and add `.env` to `.gitignore`):

```bash
# .env
API_KEY=sk-1234567890abcdef
DATABASE_URL=postgresql://...
```

### 2. API Key Permissions

Create API keys with minimal permissions:

- ✅ Read-only if possible
- ✅ Restricted to specific IP addresses
- ✅ Limited to specific endpoints
- ✅ Set usage quotas
- ✅ Enable expiration dates

### 3. Rate Limiting

Protect your proxy from abuse:

```js
const rateLimit = require('express-rate-limit');

const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 min
  max: 100, // requests per window
  message: 'Too many requests'
});

app.use('/api/', limiter);
```

### 4. Authentication

Require users to authenticate before accessing your proxy:

```js
// JWT authentication middleware
async function requireAuth(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];

  if (!token) {
    return res.status(401).json({ error: 'Unauthorized' });
  }

  try {
    const user = await verifyJWT(token);
    req.user = user;
    next();
  } catch (error) {
    res.status(401).json({ error: 'Invalid token' });
  }
}

app.get('/api/weather', requireAuth, async (req, res) => {
  // Only authenticated users can access this
  // ...
});
```

### 5. Input Validation

Always validate and sanitize user input:

```js
const { query } = require('express-validator');

app.get('/api/weather',
  query('city').trim().isLength({ min: 1, max: 100 }),
  async (req, res) => {
    const errors = validationErrors(req);
    if (errors) {
      return res.status(400).json({ errors });
    }

    // Proceed with validated input
  }
);
```

### 6. HTTPS Only

Always use HTTPS in production:

```js
// Redirect HTTP to HTTPS
app.use((req, res, next) => {
  if (req.headers['x-forwarded-proto'] !== 'https') {
    return res.redirect(`https://${req.hostname}${req.url}`);
  }
  next();
});
```

### 7. CORS Configuration

Configure CORS properly:

```js
const cors = require('cors');

app.use(cors({
  origin: 'https://your-app.com', // Specific domain
  methods: ['GET', 'POST'],
  credentials: true
}));
```

### 8. Monitoring and Alerts

Set up monitoring and alerts:

```js
// Log all API requests
app.use('/api/', (req, res, next) => {
  console.log({
    timestamp: new Date().toISOString(),
    method: req.method,
    path: req.path,
    ip: req.ip,
    userId: req.user?.id
  });
  next();
});

// Alert on unusual usage
if (requestCount > THRESHOLD) {
  sendAlert('High API usage detected');
}
```

## Serverless Options

### AWS Lambda + API Gateway

```js
// lambda/weather.js
const axios = require('axios');

exports.handler = async (event) => {
  const city = event.queryStringParameters?.city;

  if (!city) {
    return {
      statusCode: 400,
      body: JSON.stringify({ error: 'City required' })
    };
  }

  try {
    const response = await axios.get(
      'https://api.weatherapi.com/v1/current.json',
      {
        params: {
          key: process.env.WEATHER_API_KEY,
          q: city
        }
      }
    );

    return {
      statusCode: 200,
      headers: {
        'Content-Type': 'application/json',
        'Access-Control-Allow-Origin': '*'
      },
      body: JSON.stringify(response.data)
    };
  } catch (error) {
    return {
      statusCode: 500,
      body: JSON.stringify({ error: 'Request failed' })
    };
  }
};
```

## Migration Path: From SaltyKeys to Production

If you started with SaltyKeys for a demo and need to go to production:

### Step 1: Set Up Server

Create an API proxy server (see examples above).

### Step 2: Move Keys Server-Side

```bash
# .env file on server
API_KEY=your-actual-key
```

### Step 3: Update Client Code

```js
// Before (SaltyKeys)
const apiKey = SaltyKeys.getApiKey(saltedKey);
fetch(`https://api.example.com/data?key=${apiKey}`);

// After (Proxy)
fetch('/api/data');  // Your proxy handles the key
```

### Step 4: Add Security Layers

- Authentication
- Rate limiting
- Input validation
- Monitoring

### Step 5: Remove SaltyKeys

Once the proxy is in place, remove SaltyKeys from your client code.
